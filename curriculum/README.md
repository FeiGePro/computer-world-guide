# 课程总图谱

这里描述《计算机世界说明书》的大学计算机专业知识骨架。

它不是另一条必须逐篇执行的线性课程，而是把现有的 20 个一级领域继续拆成：

~~~text
知识领域 → 专业课程 → 课程模块 → 核心主题 → 文章 / 概念 / 练习
~~~

## 为什么需要这一层

现有文件分别承担不同职责：

- ARCHITECTURE.md：说明 20 个一级领域；
- paths/：提供面向读者的学习入口；
- concepts/：保存稳定概念；
- articles/：把某个问题或知识主题讲清楚；
- graph/knowledge-edges.yml：描述知识本身的关系；
- graph/learning-edges.yml：描述文章和概念怎样学习。

课程总图谱补充的是“大学专业课程如何组织”的中间层。它不替代知识图谱，也不把网状知识强行压成唯一顺序。

## 设计原则

### 1. 图谱是真实结构，路线只是观察方式

同一个课程可能有多个前置课程，也可能被不同方向重复使用。

例如，计算机网络同时连接：

- 信息表示；
- 操作系统；
- 数据库；
- 分布式系统；
- 网络安全；
- Web 和平台。

因此，推荐路线只是从图谱中选择的一条可读路径。

### 2. 简单入口不等于减少专业内容

每个专业课程都需要一个容易理解的核心问题：

- 计算机组成原理：程序怎样变成硬件执行的动作？
- 操作系统：多个程序怎样共享一台计算机？
- 计算机网络：两台计算机怎样互相传递信息？
- 数据结构与算法：同一个问题为什么有快慢不同的解决方法？

入口负责降低第一次理解的难度，后续模块仍然要逐步讲清正式概念、机制和边界。

### 3. 课程完整不等于读者已经掌握

课程文件描述“应该学什么”，文章和概念文件描述“怎样解释”，反馈和学习记录才描述“读者是否真正掌握”。

## 当前文件

- domain-map.yml：20 个领域对应的课程和模块骨架；
- learning-order.md：推荐主干与多个简单入口；
- ../graph/curriculum-edges.yml：课程级节点和关系；
- ../graph/curriculum-overview.mmd：课程主干的可视化概览。

当前版本只建立总图谱骨架。具体课程大纲、文章拆分和掌握检验将在后续分别设计。
